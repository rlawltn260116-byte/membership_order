# 아마란스 주문 수집 학습

2026-11-06 사용자가 직접 로그인한 Aside 브라우저에서 조회 화면과 엑셀 내려받기를 확인했다. 현재 단계는 절차 학습이며, 자동 수집·주문 제출·운영 연동 코드는 추가하지 않았다.

## 접속과 소속 전환

1. `https://work.hectonproject.com/#/`에 접속한다. 로그인은 사용자가 직접 수행한다. 아이디·비밀번호·인증번호는 기록하지 않는다.
2. 우측 상단 사용자 프로필을 클릭한다.
3. 프로필 패널의 소속 항목을 펼친다. `(주)조아실버케어 / 멤버십사업팀`을 선택한다. 회사·부서 변경으로 열린 업무 탭이 닫힌다는 확인창에서 ‘확인’을 누른다.
4. 우측 상단 소속 표시가 `(주)조아실버케어 멤버십사업팀`으로 바뀌었는지 확인한다. 처음 `(주)헥톤프로젝트` 소속에서는 영업관리 메뉴가 보이지 않았다. 두 소속을 혼동하지 않는다.
5. 우측 상단 돋보기로 검색을 열고 `주문미납현황`을 입력해 검색한다. 본문 검색 결과가 0건이어도 오른쪽 ‘메뉴 1 / 영업관리(1)’에 메뉴가 나타난다.
6. `주문관리 > 주문미납현황`을 클릭한다. 실제 메뉴 계층은 **영업관리 → 주문관리 → 주문미납현황**이며 관찰한 화면 경로는 `/#/BL/BLC0040/BLC0040`이다. 직접 URL만으로 소속 전환·로그인이 보장되지는 않는다.

## 조회 조건

이번에 표시된 기본 조건은 사업장·부서·사원 미지정, 기준일자 2026-11-06, 경과기준 ‘납기일자’, 주문기간 2026-11-01~2026-11-06이었다. 이는 관찰한 화면 값이며 사용자의 정식 업무 필터로 확정한 것은 아니다. 과거 주문의 미납분까지 가져오려면 주문기간 범위를 별도로 확인해야 한다.

상단 돋보기는 조회, 그 옆 아래 화살표는 추가 조회 조건 펼침이다. 펼친 조건 패널 하단에도 ‘조회’ 버튼이 있다. 메뉴 진입 후 기존 조건으로 자료가 표시됐으며, 조건 값을 변경하지 않고 해당 결과를 내보냈다.

추가 조건에서 확인한 항목:

- 품목, 품목군, 대분류, 중분류, 소분류, LOT여부, 계정구분, 조달구분
- 고객, 납품처, 고객분류, 거래구분, 환종, 실적담당, 담당그룹
- 지역, 지역그룹, 관리구분, 프로젝트, 프로젝트그룹
- 과세구분, 단가구분, 마감구분
- 주문번호, 비고(건), 납기일자 범위, 출고기간, 관리번호

사업장·부서·사원 등의 실제 코드, 각 선택 목록의 전체 값, 직배를 가르는 정식 조건은 아직 확정하지 않았다. 설정 저장 버튼은 누르지 않는다.

## 엑셀 내려받기

1. 필요한 조회 조건으로 주문미납현황 결과를 표시한다.
2. 결과 표에서 마우스 오른쪽 버튼을 누른다.
3. 우클릭 메뉴의 **엑셀변환하기**를 선택한다.
4. ‘엑셀변환하기’ 창에서 형식 및 ‘숫자 0 표시’ 항목을 확인하고 ‘확인’을 누른다. 이번에는 기본값을 변경하지 않았다. 이 ‘확인’은 파일 내보내기 창의 버튼이다.
5. 다운로드 완료를 확인하고 파일을 Git 제외 로컬 폴더에 보관한다. 이번 원본은 `.local-analysis/amaranth/unpaid-orders.xlsx`, 구조 분석 결과는 같은 폴더의 `export-structure.json`에 있다. 원본 파일과 고객정보가 있는 화면은 이 폴더 밖으로 복사하지 않는다.

파일은 XLSX 압축 무결성과 시트 XML 읽기를 확인했다. 시트 XML은 하나이며 첫 행이 머리글이다. 일반 주문행 외 합계 행도 있으므로 합계를 주문으로 처리하지 않는다. 화면 증거 역시 `.local-analysis/amaranth/`에만 보관했다.

## 기존 접수와 연결하기 전 확인할 사항

- 기존 `app/order-ops-app.tsx`는 첫 시트의 THKC 발주서 또는 일반 주문 양식을 읽는다. 화면에 아마란스 직접 연동은 준비 중으로 표시한다. 아마란스 원본과 동일한 양식으로 간주하면 안 된다.
- 주문번호만으로 중복 제거하면 같은 주문의 여러 품목이 합쳐진다. `주문번호 + 순번`은 이번 표본에서 중복이 없는 행 키 후보였지만, 정식 키·수정 이력 처리 방식은 별도 확인한다. `No`는 표시용 순서이므로 영구 식별자로 쓰지 않는다.
- `주문수량`과 `미납수량`이 다른 행이 실제 존재한다. 미납 처리용 수량을 어느 값으로 삼을지 업무 기준을 확인한다.
- `납품처` 및 `비고(건)`·`비고(내역)`에 배송지·연락처·수취인 등의 정보가 섞일 수 있다. 이 원본에는 THKC의 독립된 `납품처전화번호` 열이 없다. 배송정보를 정식으로 분리하는 규칙을 확인해야 한다.
- `관리구분`, `품목군`, 비고의 직배 표현은 후보 정보다. 직배 대상·제외·취소·수정·마감 상태에 대한 확정 규칙으로 사용하지 않는다.
- 기간을 넓힌 미납 주문의 범위, 재조회 시 중복·감소·소멸 처리, 필요한 배송정보의 원천, 품번과 업체 상품의 연결을 확인한 뒤 자동 수집 설계를 진행한다.

## 보관과 실행 범위

추적 문서에는 절차와 열 구조만 남겼다. 고객 이름·주소·전화번호, 업체 연락처, 실제 단가·금액, 사용자 실명, 로그인 정보는 기록하지 않는다. 소속 전환과 조회 화면 탐색·엑셀 내려받기 외 저장·수정·삭제·승인·전표 처리·실제 발주·메일/팩스/카톡 발송·Firebase 변경·workflow 실행·커밋·푸시는 하지 않았다.

과거 발주서 로컬 학습 자료에서는 아마란스 관련 출처·미납 메모를 확인했으나 화면 절차를 확정할 수 없어, 위 절차는 이번 사용자 설명과 실제 브라우저 확인을 기준으로 정리했다.
