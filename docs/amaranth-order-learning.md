# 아마란스 주문 수집 학습

2026-11-06 사용자가 직접 로그인한 Aside 브라우저에서 조회 화면과 엑셀 내려받기를 확인했다. 이후 확정한 수집 기준을 로컬 분석 전용 파서에 반영했다. 자동 수집·주문 제출·운영 연동은 하지 않는다.

## 접속과 소속 전환

1. `https://work.hectonproject.com/#/`에 접속한다. 로그인은 사용자가 직접 수행한다. 아이디·비밀번호·인증번호는 기록하지 않는다.
2. 우측 상단 사용자 프로필을 클릭한다.
3. 프로필 패널의 소속 항목을 펼친다. `(주)조아실버케어 / 멤버십사업팀`을 선택한다. 회사·부서 변경으로 열린 업무 탭이 닫힌다는 확인창에서 ‘확인’을 누른다.
4. 우측 상단 소속 표시가 `(주)조아실버케어 멤버십사업팀`으로 바뀌었는지 확인한다. 처음 `(주)헥톤프로젝트` 소속에서는 영업관리 메뉴가 보이지 않았다. 두 소속을 혼동하지 않는다.
5. 우측 상단 돋보기로 검색을 열고 `주문미납현황`을 입력해 검색한다. 본문 검색 결과가 0건이어도 오른쪽 ‘메뉴 1 / 영업관리(1)’에 메뉴가 나타난다.
6. `주문관리 > 주문미납현황`을 클릭한다. 실제 메뉴 계층은 **영업관리 → 주문관리 → 주문미납현황**이며 관찰한 화면 경로는 `/#/BL/BLC0040/BLC0040`이다. 직접 URL만으로 소속 전환·로그인이 보장되지는 않는다.

## 조회 조건

이번에 표시된 기본 조건은 사업장·부서·사원 미지정, 기준일자 2026-11-06, 경과기준 ‘납기일자’, 주문기간 2026-11-01~2026-11-06이었다. 사용자가 확정한 주문 조회 기간은 **최근 30일**이다. 파서는 기준일을 포함한 30개 달력일로 계산한다(2026-11-06 기준 2026-10-08~2026-11-06). 이 포함 방식은 구현에서 명시한 기준이다. 로컬 표본의 실제 주문일자는 11월 2~6일로, 30일 전체를 조회한 자료는 아니다.

상단 돋보기는 조회, 그 옆 아래 화살표는 추가 조회 조건 펼침이다. 펼친 조건 패널 하단에도 ‘조회’ 버튼이 있다. 메뉴 진입 후 기존 조건으로 자료가 표시됐으며, 조건 값을 변경하지 않고 해당 결과를 내보냈다.

추가 조건에서 확인한 항목:

- 품목, 품목군, 대분류, 중분류, 소분류, LOT여부, 계정구분, 조달구분
- 고객, 납품처, 고객분류, 거래구분, 환종, 실적담당, 담당그룹
- 지역, 지역그룹, 관리구분, 프로젝트, 프로젝트그룹
- 과세구분, 단가구분, 마감구분
- 주문번호, 비고(건), 납기일자 범위, 출고기간, 관리번호

사업장·부서·사원 등의 실제 코드와 각 선택 목록의 전체 값은 아직 확정하지 않았다. 직배 여부는 소분류의 업체명으로 판정한다. 설정 저장 버튼은 누르지 않는다.

## 엑셀 내려받기

1. 필요한 조회 조건으로 주문미납현황 결과를 표시한다.
2. 결과 표에서 마우스 오른쪽 버튼을 누른다.
3. 우클릭 메뉴의 **엑셀변환하기**를 선택한다.
4. ‘엑셀변환하기’ 창에서 형식 및 ‘숫자 0 표시’ 항목을 확인하고 ‘확인’을 누른다. 이번에는 기본값을 변경하지 않았다. 이 ‘확인’은 파일 내보내기 창의 버튼이다.
5. 다운로드 완료를 확인하고 파일을 Git 제외 로컬 폴더에 보관한다. 이번 원본은 `.local-analysis/amaranth/unpaid-orders.xlsx`, 구조 분석 결과는 같은 폴더의 `export-structure.json`에 있다. 원본 파일과 고객정보가 있는 화면은 이 폴더 밖으로 복사하지 않는다.

파일은 XLSX 압축 무결성과 시트 XML 읽기를 확인했다. 시트 XML은 하나이며 첫 행이 머리글이다. 일반 주문행 외 합계 행도 있으므로 합계를 주문으로 처리하지 않는다. 화면 증거 역시 `.local-analysis/amaranth/`에만 보관했다.

## 확정한 수집·제외 기준

- 소분류 값이 업체명이면 직배다. 표본에서는 `직배(업체명)` 형태가 확인됐다. 소분류 누락은 입력 누락 가능성이 있으므로 별도 예외로 분리하며, 보정·재처리는 후속 작업이다. 비고의 직배 문구로 대체 판정하지 않는다.
- 주문수량과 미납수량이 다른 행은 이미 주문이 들어가 일부 출고된 건이므로, 같은 주문번호의 모든 행을 제외한다. 미납수량만 새 주문으로 만들지 않는다.
- 출고 처리된 건은 조회 목록에서 사라진다. 이미 처리한 주문번호가 남아 있으면 그 번호의 모든 행을 제외한다. 처리 이력은 주문번호 단위로 보관해야 한다. 현재 순수 파서는 외부에서 받은 `processedOrderNumbers` 집합만 읽고, 이력을 쓰거나 처리 완료로 표시하지 않는다.
- 신규 주문의 여러 품목은 `주문번호 + 순번`으로 유지한다. 같은 번호의 서로 다른 품목을 중복 주문으로 지우지 않는다. 동일 행 키 반복, 빈 행 키, 잘못된 날짜·수량은 예외다. `No`는 영구 식별자가 아니다.
- 배송정보는 비고를 우선하고 없으면 납품처로 보완한다. 필드별 우선순위는 `비고(건)` → `비고(내역)` → `납품처`다. 표본의 비어 있지 않은 셀은 각각 546, 329, 567개이고, 전화번호 패턴이 있는 셀은 각각 273, 52, 0개였다. 따라서 건 비고를 먼저 읽는 것이 표본에 부합한다. 두 비고가 충돌할 때의 정식 업무 규칙은 아직 확인하지 않았으며 파서는 위 순서를 적용한다.
- 표본의 비고에는 수취인·주소 명시 라벨이 없었다. 자유형 이름을 추측하지 않고 수취인 라벨, 주소 패턴, 전화번호를 분리하며, 필수 필드가 부족하면 `delivery.needsReview`로 남긴다. 이 결과는 발주에 사용할 검증 완료 데이터가 아니다. 비고 원문은 반환값의 `deliveryNotes`에만 남으며 로컬 밖으로 저장하지 않는다.

## 로컬 파서와 검증

`tools/parse_amaranth_orders.mjs`는 첫 시트를 읽는 `readAmaranthWorkbook(path)`와 순수 함수 `parseAmaranthRows(rows, { asOf, processedOrderNumbers, suppliers })`를 제공한다. `supplierLookup(schedule, aliases)`로 시간표의 업체명·앱 채널을 대응시킨다. 검증한 별칭만 호출자가 전달하며, 시간·품목 접미사를 자동으로 제거하지 않는다. 필수 열 누락·중복은 읽기 단계에서 중단한다.

반환값은 `bySupplier`(업체별 후보), `excluded`(기처리·수량 차이·기간 밖·0수량), `exceptions`(누락·미대응·중복·잘못된 값), `totalsRemoved`다. 합계·소계와 빈 행은 주문으로 가져오지 않는다. 후보에도 배송 검토 필요 건이 있을 수 있으므로 자동 제출에 연결하지 않는다. 실제 처리 이력 저장소와 원자적 중복 방지는 이번 범위에 포함하지 않는다.

모의 데이터 검증 명령: `node --test tools/parse_amaranth_orders.test.mjs`. 시험에는 실제 고객정보·업체 연락처·단가를 사용하지 않는다. 실제 표본은 읽기·집계만 수행한다.

현재 로컬 표본 검증 결과: 822행 중 합계 1행 제거, 수량 차이 6행 제외, 소분류 누락 432행 및 업체 미대응 175행 예외, 분류 후보 208행이다. 후보 208행 모두 수취인 자동 확정이 어려워 배송 검토가 필요하다. 처리 이력은 제공되지 않아 이 표본 집계에는 빈 집합을 사용했으며, 기처리 주문번호 전체 제외는 모의 시험으로 검증했다. 30일 전체 정확도와 자유형 수취인 해석은 이번 결과로 보장하지 않는다.

시간표와의 불일치(고객정보 제외): `직배(용인창고)`, `직배(남양금속)`은 현재 시간표 업체에 없다. `직배(선인케어)`와 시간표 `선인케어`는 철자가 다르다. `직배(THKC)_오전`, `직배(THKC)_오후`는 시간표 `THK`/앱 채널 `이로움`과 명칭이 다르며, `직배(안앤락-1130)`, `직배(안앤락-보행기)`, `직배 (안앤락-13시)`는 `안앤락`과 세부 구분이 다르다. 이 값들은 명시적 대응 승인 전 `unmapped_subcategory` 예외로 둔다. 나머지 업체는 `직배(...)` 포장과 공백을 제거한 이름으로 대응한다.

## 기존 접수와 연결하기 전 남은 사항

- 기존 `app/order-ops-app.tsx`는 첫 시트의 THKC 발주서 또는 일반 주문 양식을 읽는다. 화면에 아마란스 직접 연동은 준비 중으로 표시한다. 아마란스 원본과 동일한 양식으로 간주하면 안 된다.
- 자유형 배송정보의 모호한 구분, 취소·수정·마감 상태, 품번과 업체 상품의 연결은 별도 확인한다. `관리구분`·`품목군`·비고의 직배 표현을 확정 필터로 쓰지 않는다.
- 최근 30일 전체 표본 검증, 처리 주문번호 영속 기록 설계와 미대응 업체 확인 후 운영 연결을 검토한다. 이번 파서를 주문 큐, `SUBMIT_QUEUED`, 메일·팩스·카톡, Firebase, workflow와 연결하지 않는다.

## 보관과 실행 범위

추적 문서에는 절차와 열 구조만 남겼다. 고객 이름·주소·전화번호, 업체 연락처, 실제 단가·금액, 사용자 실명, 로그인 정보는 기록하지 않는다. 소속 전환과 조회 화면 탐색·엑셀 내려받기 외 저장·수정·삭제·승인·전표 처리·실제 발주·메일/팩스/카톡 발송·Firebase 변경·workflow 실행·커밋·푸시는 하지 않았다.

과거 발주서 로컬 학습 자료에서는 아마란스 관련 출처·미납 메모를 확인했으나 화면 절차를 확정할 수 없어, 위 절차는 이번 사용자 설명과 실제 브라우저 확인을 기준으로 정리했다.
