# 보필몰 장바구니 담기 절차 학습

2026-11-06 보필몰(https://bofeelmall.com/)에서 로그인부터 장바구니 담기까지 진행하고, 옵션 상품 담기와 주문서 화면 읽기까지 확인한 기록이다. 자동화 코드는 만들지 않았고, 주문은 제출하지 않았다. 로그인 정보, 고객정보, 단가는 이 문서에 넣지 않는다.

## 최초 시험 결과 (BFSH10)

이 표는 최초 `BFSH10` 시험 시점의 기록이다. 이후 재시험은 `옵션 상품 시험`과 `주문서 화면 구조`를 본다.

| 항목 | 결과 |
| --- | --- |
| 로그인 | 1회에 성공. 캡차·추가 인증 없음 |
| 담기 전 장바구니 | 비어 있음(`장바구니에 담겨있는 상품이 없습니다.`) |
| 담은 상품 | `BFSH10`(안전손잡이), 수량 1, 옵션 없음 |
| 담은 후 장바구니 | `BFSH10` 1건, `총 1 개` |
| 시험 후 상태 | 시험 상품은 사용자가 직접 삭제함(2026-11-06) |
| 누르지 않은 버튼 | `바로 구매`, `선택 상품 주문`, `전체 상품 주문`, `선택 상품 삭제`, `옵션/수량변경` |

상품은 `직배(보필) 발주서` 최신본(2026-10-07)의 품명 `안전손잡이 BFSH10`에서 골랐다. 품명 열만 읽었다. 옵션이 없어 첫 시험에서 잘못 고를 위험이 가장 낮기 때문이다.

## 절차

### 1. 로그인

1. 상단의 `로그인` 링크로 `/member/login.php`에 들어간다.
2. `form#formLogin`의 아이디·비밀번호 칸(자리표시자 `아이디`, `비밀번호`)을 채운다. 아이디 저장이 켜져 있으면 아이디가 미리 채워져 있을 수 있다.
3. `button.member_login_order_btn`(`로그인`)을 누른다. 같은 폼에 `회원가입`, `아이디 찾기`, `비밀번호 찾기` 제출 버튼이 함께 있으므로 버튼을 글자나 클래스로 구분한다.
4. 성공하면 `/main/index.php`로 이동하고 상단 링크가 `로그인`에서 `로그아웃`으로 바뀐다. 알림창은 뜨지 않았다.

### 2. 메뉴와 상품 찾기

상단 메뉴는 `공지사항`, `신규유통상품`, `복지용구(구입품목)`, `복지용구(대여품목)`, `장애인/비급여`, `회사소개`다. `BFSH10`의 분류 경로는 `복지용구(구입품목) > 안전손잡이`다.

메뉴를 타고 들어가기보다 모델명 검색이 빠르고 정확했다.

- 상단 검색창에 모델명을 넣고 Enter를 누르면 `/goods/goods_search.php?keyword=<모델명>&recentCount=10`으로 이동한다. `keyword`만 준 주소도 같은 결과 화면이 열렸다.
- `#frmSearchTop` 안의 입력칸은 3개이고 그중 일부만 화면에 보인다. 자동화할 때는 보이는 칸을 골라야 한다.
- 결과 화면의 `"<검색어>" 검색결과 N개`로 건수를 확인한다. `BFSH10`, `BFMB20` 모두 1건이었다. 결과 화면에는 다른 상품 링크도 섞여 있을 수 있으므로 링크 전체를 세지 말고 상품명 일치를 확인한다.
- 상품 상세 주소는 `/goods/goods_view.php?goodsNo=<상품번호>`다.

### 3. 상품 상세와 옵션

상세 화면의 주문 영역은 `form#frmView`다. 수량 칸의 기본값은 1이고 `증가`, `감소` 버튼이 옆에 있다.

| 상품 | 옵션 구성 |
| --- | --- |
| `BFSH10` | 옵션 없음. 수량 표에 상품이 바로 나옴 |
| `BFMB20` | `select[name=optionSnoInput]`에 `파스텔브라운`, `파스텔블루` 2개 |

옵션 `select`는 `chosen-select` 클래스로 숨겨져 있고 화면에는 chosen 드롭다운이 대신 표시된다. `BFMB20`은 2026-11-06 재시험에서 실제 클릭으로 옵션을 고르고 담았다(아래 `옵션 상품 시험` 참고).

발주서와 사이트의 이름이 다르다. 예를 들어 발주서의 `이동변기 BFMB20 / 블루`는 사이트에서 상품명 `BFMB20`, 옵션 `파스텔블루`로 보인다. 품명을 그대로 검색하면 맞지 않으므로 품목군을 빼고 모델명만 검색해야 하고, 색상은 옵션 이름과 대응표가 필요하다. 이번에 확인한 대응은 `BFSH10`, `BFMB20`뿐이다.

### 4. 장바구니 담기

담기 전에 장바구니를 읽기만 해서 먼저 확인한다. 기존 항목이나 예상 밖 수량이 있으면 추가로 담지 말고, 삭제나 변경도 하지 말고 중단한다. 이번 시험 상품이 삭제되지 않았다면 다음 시험에서 바로 이 경우에 해당한다.

1. 수량과 옵션을 확인한다.
2. `button#cartBtn`(`.btn_add_cart`, `장바구니`)을 한 번 누른다. 바로 옆의 `.btn_add_order`(`바로 구매`)와 혼동하면 안 된다.
3. 같은 화면에 `장바구니 담기` 안내창이 뜬다. 문구는 `상품이 장바구니에 담겼습니다.바로 확인하시겠습니까?`이고 버튼은 `쇼핑 계속하기`, `장바구니 확인`, `닫기`다.
4. `장바구니 확인`을 누르면 `/order/cart.php`로 이동한다.

클릭 후 응답이 없거나 결과가 불명확해도 다시 누르지 않는다. 같은 상품을 다시 담았을 때의 동작을 시험하지 않았으므로 중복으로 담길 수 있다고 보고, 장바구니를 먼저 다시 조회한다. 기대한 모델·옵션·수량과 정확히 일치하면 끝내고, 다르면 수정하지 말고 중단해 보고한다.

### 5. 장바구니 확인

- 장바구니 폼은 `form#frmCart`다. 비어 있으면 `장바구니에 담겨있는 상품이 없습니다.`가 나온다.
- 상품 행의 체크박스는 `input[name="cartSno[]"]`이고 id는 `cartSno1_<번호>` 형식이다.
- 화면 DOM에서 세면 행 수가 정확하다. HTML 원문을 문자열로 세면 페이지 안의 템플릿까지 잡혀 실제보다 많게 나온다. 이번에도 원문 검색은 11건, 실제 행은 1건이었다.
- 합계 영역의 `총 N 개`는 담긴 상품 수 확인에 쓸 수 있다.
- 배송 칸에 배송 조건과 `택배-선결제` 방식이 표시된다.

## 눌러서는 안 되는 요소

아래는 장바구니까지만 하는 작업에서 누르면 안 되는 요소다. `전체 상품 주문`은 주문서 화면 읽기가 승인된 시험에서만 한 번 눌렀고, 나머지는 누르지 않았다.

| 화면 | 요소 | 위험 |
| --- | --- | --- |
| 상품 상세 | `.btn_add_order`(`바로 구매`) | 주문서 작성으로 이동 |
| 장바구니 | `.btn_order_choice_buy`(`선택 상품 주문`) | 주문서 작성으로 이동 |
| 장바구니 | `.btn_order_whole_buy`(`전체 상품 주문`) | 주문서 작성으로 이동 |
| 장바구니 | `.btn_order_choice_del`(`선택 상품 삭제`) | 장바구니 항목 삭제 |
| 장바구니 | `옵션/수량변경` | 담긴 항목 변경 |

장바구니 단계 표시는 `01 장바구니`, `02 주문서작성/결제`, `03 주문완료`다.

## 옵션 상품 시험 (2026-11-06, 주문 없음)

사용자 승인 범위는 `BFMB20` 파스텔블루 1개 담기와 주문서 화면 읽기까지다. 시작 전 장바구니는 비어 있었다. 지시에 따라 `BFMB20` 파스텔블루 1개를 장바구니에 남겨 두었고, 별도 삭제 지시 전에는 삭제하지 않는다.

1. 검색 결과 1건을 확인하고 상세 화면(`goodsNo=1000000674`)으로 들어간다.
2. `form#frmView .chosen-single`을 실제 마우스로 클릭해 목록을 연다. `.chosen-results li`에 `= 옵션 : 가격 =`, `파스텔브라운`, `파스텔블루`가 나온다.
3. `파스텔블루` 항목을 실제 마우스로 클릭한다. `select` 값 강제 주입은 쓰지 않았다.
4. 고른 뒤 드롭다운 표시는 `= 옵션 : 가격 =`으로 돌아가고 숨은 `select`도 다시 비어 보인다. 대신 아래에 `파스텔블루` 행과 수량 칸 `goodsCnt[]`(값 1)이 생긴다. **선택 결과는 드롭다운 글자가 아니라 추가된 행으로 확인한다.**
5. `#cartBtn`의 글자와 클릭 지점을 확인하고 한 번 누른다. 같은 화면에 `상품이 장바구니에 담겼습니다.` 안내가 뜬다.
6. `/order/cart.php`를 열어 1행, `총 1 개`, `BFMB20`, `색상 : 파스텔블루`, `1개`를 대조했다.

## 주문서 화면 구조

장바구니의 `전체 상품 주문`(`gd_order_all()`)을 한 번 눌러 `/order/order.php`(`주문서작성/결제`)로 이동했다. 입력, 라디오 변경, 체크, 결제 버튼 조작 없이 구조만 읽고 떠났다. 떠난 뒤에도 장바구니는 유지됐다. 실제 주소, 연락처, 계좌, 금액은 기록하지 않는다.

폼은 `form#frmOrder`이고 `./order_ps.php`로 POST한다.

| 영역 | 요소 | 비고 |
| --- | --- | --- |
| 주문 상품 | 상품, 옵션, 수량, 금액, 배송 표시 | 단계 표시가 `02 주문서작성/결제`로 나온다 |
| 주문자 정보 | `orderName`, `orderPhone`, `orderCellPhone`, `orderEmail` | 회원 정보로 채워져 있다 |
| 배송지 선택 | 라디오 `shipping`: `shippingBasic`(`기본 배송지`), `shippingRecently`(`최근 배송지`), `shippingNew`(`직접 입력`), `shippingSameCheck`(`주문자정보와 동일`), 옆에 `배송지 관리` | 기본 선택은 `기본 배송지`다. 다른 항목은 누르지 않아 목록 구성은 모른다 |
| 받으실 곳 | `receiverName`, `receiverZonecode`, `receiverAddress`, `receiverAddressSub`, `receiverPhone`, `receiverCellPhone`, `.btn_post_search`(`우편번호검색`) | 전화번호를 뺀 칸이 채워져 있다. 우편번호와 주소 칸은 읽기 전용이다 |
| 요청사항 | `orderMemo`(`남기실 말씀`) | 비어 있다 |
| 회원정보 반영 | 체크박스 `reflectApplyDelivery`(`나의 배송지에 추가합니다.`) | 회원 배송지 정보가 바뀔 수 있으므로 체크하지 않는다 |
| 쿠폰 | `쿠폰 조회 및 적용` | 누르지 않았다 |
| 결제수단 | 라디오 `settleKind`(`settleKind_gb`, `무통장 입금`), `bankAccount` 선택 칸 | 이 계정에서 보이는 방식은 무통장 입금 하나이고 이미 선택돼 있다 |
| 약관 동의 | 체크박스 `termAgree_orderCheck`(`(필수) ... 구매진행에 동의합니다.`) | 체크하지 않았다 |
| 최종 버튼 | `.btn_order_buy.order-buy`(`결제하기`) | **절대 누르지 않는다** |

받으실 곳 칸은 주문당 한 벌이고 품목별 배송지 칸은 보이지 않았다. 납품처가 다른 품목은 주문을 나눠야 할 것으로 보이지만, 주문을 제출하지 않았으므로 확정이 아니다.

필수 동의 항목과 최종 버튼 `결제하기`를 관찰했다. 무통장 입금이 이미 선택된 상태이므로 주문 생성 위험이 있다고 보고 둘 다 조작하지 않는다. 다른 필수값과 실제 접수 동작은 확인되지 않았다.

## 새 주문이 없음을 확인하는 법

`/mypage/order_list.php`를 읽기 전용으로 연다. 기본 조회 기간은 최근 일주일이고 최신순이다. 주문번호 앞 10자리는 시각(`YYMMDDHHMM`)으로 보인다. 시험 시작 시각 이후의 번호가 없는지, 시험 상품이 없는지 비교한다. 이번 시험은 18시대였고 최신 주문은 그날 오전 번호였으며 `BFMB20`은 없었다. 이 목록에는 수취인이 나오므로 내용을 문서로 옮기지 않는다.

## 확인되지 않은 것

- 시험으로 담은 `BFSH10`은 사용자가 직접 삭제했다. 보필 장바구니 삭제 절차는 시험하지 않았다. 재시험의 `BFMB20` 1개는 별도 삭제 지시가 있을 때까지 남겨 둔다.
- 보필 발주마감의 기준은 시간표의 09:00이다(사용자 확인). 사이트의 `오후 3시 (업체별 상이)`, 상품별 `2시 30분 마감` 표시는 기준으로 쓰지 않는다.
- 수량 2개 이상, 같은 상품 재담기, 여러 상품 담기는 시험하지 않았다.
- 품절·출고 지연 상품의 표시는 보지 못했다. 사이트 공지에 출고 지연 안내가 따로 올라온다.
- 납품처별로 주문을 나누는 실제 절차와 배송지 입력은 주문을 제출하지 않아 확인하지 못했다. `직접 입력`과 `최근 배송지`를 골랐을 때의 화면도 보지 않았다. 직배는 고객별 납품처가 다르므로 자동화 전에 가장 먼저 풀어야 할 항목이다.
- 발주서의 `동행(sk-130)` 같은 표기가 사이트에서 어떤 상품명으로 검색되는지는 시험하지 않았다.

캡처는 저장소에서 제외되는 `.local-analysis/bofeel/`에만 저장했다. 비밀번호 입력 화면은 캡처하지 않았다. 주문서 캡처는 생성됐지만 REPL 세션 폴더에서 저장소로 옮기기 전에 그 폴더가 없어져 보존하지 못했다. 구조는 이 문서와 `.local-analysis/bofeel/orderform-evidence.txt`로 남겼다. 장바구니 캡처는 `07-cart-bfmb20.png`로 저장했다.

## 신규 배송지 입력 시험 (2026-11-06, 제출 없음)

앞선 미확인 사항 중 `직접 입력` 동작을 이번에 확인했다. 향후 배송지는 항상 `직접 입력`(`label[for=shippingNew]`)으로 시작하며 기본·최근 배송지와 배송지 관리 목록은 쓰지 않는다.

- 시작 장바구니는 빈 상태였다. BFSH10 수량 1을 한 번 담고 `/order/cart.php`에서 단일 행과 수량 1을 대조한 뒤 `전체 상품 주문`으로 주문서를 열었다.
- `직접 입력` 선택 시 `receiverName`, `receiverZonecode`, `receiverAddress`, `receiverAddressSub`, `receiverPhone`, `receiverCellPhone`이 비워졌다.
- 수취인 `receiverName`, 전화 `receiverPhone`, 휴대폰 `receiverCellPhone`, 요청사항 `orderMemo`는 일반 입력으로 시험값이 반영됐다.
- `.btn_post_search`는 별도 `우편번호 찾기` 팝업(`/share/postcode_search.php`)을 연다. 검색어 칸에 공공 시험 주소를 입력하고 `검색` 버튼을 클릭하면 도로명·지번 결과가 표시된다. 입력칸에서 Enter는 쓰지 않았다.
- 도로명 결과를 클릭하면 팝업이 닫히고 `receiverZonecode` 및 읽기 전용 `receiverAddress`가 채워진다. **주소 선택 시 `receiverAddressSub`가 비워지므로 상세주소는 주소 검색 완료 후 입력한다.** 이를 위해 주문서를 다시 열어 검색 후 상세주소를 입력했고, 수취인·전화·휴대폰·우편번호·주소·상세주소·요청사항의 시험값 반영을 모두 확인했다.
- 입력 중 관찰한 오류 문구는 없었다. 필드의 HTML `required` 속성은 없었으며 제출 검증은 실행하지 않았다. 필수 구매진행 동의는 미선택으로 유지했다.
- `reflectApplyDelivery`는 미선택, 결제수단은 변경하지 않았고 `.btn_order_buy`는 누르지 않았다. 배송지 저장·회원정보 변경·함수 직접 호출은 하지 않았다.
- 제출 없이 장바구니로 돌아와 BFSH10 단일 행만 있는 것을 대조하고 `선택 상품 삭제`를 한 번 눌렀다. 빈 장바구니 문구와 총 0개를 확인했다. 이로써 보필 선택 상품 삭제 절차도 확인했다.
- 주문내역의 최신 번호 시각은 당일 오전이었고 시험 시각 이후 주문은 없었다. 고객정보·회사 주소·단가는 기록하지 않는다.
