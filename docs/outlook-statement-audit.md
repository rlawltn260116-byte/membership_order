## 조사 방법과 한계

- 사용자의 로그인된 Aside 브라우저에서 공용 사서함 검색을 사용했다. 검색 결과가 안정화된 뒤 가상 목록을 겹쳐 내려가며 화면에 로드된 행을 수집하고, 목록 끝의 위치·높이·표시 행이 반복해서 같음을 확인했다.
- 동일 검색 내에서는 화면의 대화 식별값과 행 설명 조합으로 반복 수집을 제거했다. 이 값은 실제 개별 메일 식별값과 다를 수 있다. 대화 묶음·동일 발송·첨부 중복을 검증한 결과가 아니다.
- 검색 기간은 제한하지 않았다. Outlook의 검색 색인·검색어 해석·결과 제한 때문에 전체 수신 이력을 빠짐없이 조사했다고 보장할 수 없다. 업체별 발신 주소 대조도 수행하지 않았다.
- `isread:yes`와 `isread:true`를 붙인 초기 탐색은 결과가 없어 집계에 쓰지 않았다. 최종 집계는 실제 각 결과 행의 `읽지 않음` 표시를 확인했다. 초기 안정화 미확인 수집도 최종 집계에서 제외했다.
- 행의 `읽지 않음` 표시는 접근성 설명을 기준으로 관찰했다. 사서함 전체 배지의 읽지 않음 수와 검색 행 합계는 서로 달랐으며, 검색 범위·대화 묶음·표시 방식에 따른 차이인지는 확인하지 못했다. 사용자가 이미 읽은 것으로 아는 메일과의 교차 대조도 하지 않았다. 따라서 실제 읽은 메일이 전혀 없다고 확정하지 않으며, 표시가 불확실한 메시지도 열지 않는 쪽으로 처리했다.
- 이미 읽은 것으로 확인된 결과 행은 0개였다. 읽음 상태를 바꾸는 동작, 메시지 열기, 첨부 미리보기·내려받기, 전송·이동·삭제·플래그 조작은 하지 않았다. 아마란스 등록과 발주도 실행하지 않았다.
- 목록 원문·화면 증거·수집 스크립트는 Git 제외 경로 `.local-analysis/outlook-statement/`에만 보관했다. 공개 문서에는 업체명·검색어·집계·한계만 기록했다.

## 미확인 항목과 다음 조건

본문인지 첨부인지, PDF·엑셀·이미지 종류, 수신자·주소·품목·규격·수량·단가·금액·문서번호·일자 위치는 모두 미확인이다. 다품목·부분 납품·정정·반품·합계 오류·중복 발송의 빈도와 발주서 연결 실패율도 계산할 수 없다. 미검수 자료를 정상이나 예외 0건으로 처리하지 않는다.

본문 검수를 이어가려면 이미 읽은 메일 또는 별도로 제공된 명세서 원본이 필요하다. 현재의 ‘읽지 않은 메일은 열지 않고 건수만 확인’ 조건은 유지한다. 회사 계정의 커넥터 관리자 승인 문제는 해결하지 않았으며, 브라우저 목록 조회 성공을 자동 수신 연동 완료로 보지 않는다.
